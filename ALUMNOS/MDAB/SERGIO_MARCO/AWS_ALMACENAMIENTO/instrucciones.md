# INSTRUCTIONS FOR MVP: AWS DELIVERY FLEET MANAGEMENT SYSTEM

You are an expert cloud developer and DevOps engineer. Your task is to generate a complete, production-ready MVP for a Delivery Fleet Management System deployed on AWS using Terraform. The entire architecture must be provisioned and deployed using a single monolithic script called `deploy.sh`.

## 1. PROJECT OVERVIEW & ARCHITECTURE
We need a cost-effective, simple architecture that allows learning Kubernetes without enterprise overhead costs (No Amazon EKS unless specified).
- **Database:** Amazon RDS PostgreSQL (`db.t4g.micro` or `db.t3.micro` for Free Tier safety).
- **Compute:** A single Amazon EC2 Instance (`t3.small`) acting as a single-node Kubernetes cluster using **K3s** (lightweight Kubernetes).
- **Frontend:** Single Page Application (HTML/JS) using Leaflet.js and OpenStreetMap (100% Free, no API keys needed). It must show a map with vehicle markers and route polylines representing paths to targets. It also includes an admin dashboard form to CRUD data.
- **Backend:** A lightweight API (Python FastAPI or Node.js Express) inside a Docker container, running as a Kubernetes deployment.

---

## 2. DATABASE MODEL (PostgreSQL)
Generate the database schema script (`schema.sql`) with the following tables and relationships:

1. **conductores (Drivers):**
   - `id`: SERIAL PRIMARY KEY
   - `dni`: VARCHAR(20) UNIQUE NOT NULL
   - `nombre`: VARCHAR(100) NOT NULL
   - `telefono`: VARCHAR(20)

2. **vehiculos (Vehicles):**
   - `id`: SERIAL PRIMARY KEY
   - `matricula`: VARCHAR(20) UNIQUE NOT NULL
   - `modelo`: VARCHAR(50) NOT NULL
   - `capacidad_carga_kg`: NUMERIC(10,2) NOT NULL
   - `fecha_itv`: DATE NOT NULL (Date of next technical inspection)
   - `estado`: VARCHAR(20) DEFAULT 'disponible' (disponible, en_ruta, taller)

3. **rutas (Routes):**
   - `id`: SERIAL PRIMARY KEY
   - `vehiculo_id`: INTEGER REFERENCES vehiculos(id)
   - `conductor_id`: INTEGER REFERENCES conductores(id)
   - `origen_lat`: NUMERIC(9,6), `origen_lng`: NUMERIC(9,6)
   - `destino_lat`: NUMERIC(9,6), `destino_lng`: NUMERIC(9,6)
   - `actual_lat`: NUMERIC(9,6), `actual_lng`: NUMERIC(9,6) -- For live map simulation
   - `estado`: VARCHAR(20) DEFAULT 'pendiente' (pendiente, en_ruta, completada)

---

## 3. BUSINESS LOGIC & ALERTS (API Requirements)
The backend API must expose endpoints to CRUD drivers, vehicles, and routes, plus endpoints to calculate specific MVP metrics:
- **Alert 1 (ITV Inspection):** Flag an alert if `fecha_itv` is less than 30 days away from current date.
- **Alert 2 (Overload):** Flag an alert if a route payload (can be added to route table or simulated) exceeds 90% of the vehicle's capacity.
- **Route Tracking Endpoint:** Returns the origin, destination, and current coordinates of active routes so the frontend can plot the map.

---

## 4. TERRAFORM REQUIREMENTS
Create a `terraform/` directory with the infrastructure definition:
- `main.tf`, `variables.tf`, `outputs.tf`
- **VPC & Networking:** A simple public subnet for EC2, and a private subnet group for RDS.
- **RDS Instance:** `aws_db_instance` configuring PostgreSQL, t4g.micro, publicly accessible set to false. Security Group must only allow traffic from the EC2 Security Group.
- **EC2 Instance:** `aws_instance` with Ubuntu Server 22.04 LTS. Security Group must open ports 22 (SSH), 80 (HTTP Web/API redirection), and 443.
- **User Data Script:** The EC2 must automatically install Docker, and install **K3s** (`curl -sfL https://get.k3s.io | sh -`).

---

## 5. KUBERNETES MANIFESTS
Inside a `k8s/` directory, create standard manifests to run the application:
- `backend-deployment.yaml` & `backend-service.yaml` (Exposing the containerized API).
- `frontend-deployment.yaml` & `frontend-service.yaml` (Serving the static HTML/JS files using Nginx).
- Environment variables must inject the RDS endpoint, DB name, user, and password generated by Terraform into the backend pod.

---

## 6. FRONTEND SPECIFICATIONS
Create a clean dashboard UI split into two sections:
1. **Admin Panel:** Simple HTML forms to register new vehicles, drivers, and assign routes. Tables to view the current lists.
2. **Live Tracking Map:** - Integrate **Leaflet.js** map container.
   - Fetch active routes from the API.
   - For each active route, place a custom marker at `actual_lat/lng`.
   - Draw a visible routing line (Polyline) connecting `origen` -> `actual` -> `destino`.
   - Display active alerts prominently if any vehicle triggers the 30-day ITV limit.

---

## 7. THE MASTER DEPLOYMENT SCRIPT (`deploy.sh`)
Create a root-level bash script `deploy.sh` that automates everything from zero. It must execute the following steps in sequence:

1. **Infrastructure Provisioning:**
   - Run `terraform init` and `terraform apply -auto-approve`.
   - Extract outputs: RDS Host endpoint and EC2 Public IP.
2. **Database Initialization:**
   - Wait for RDS to become healthy, then run the `schema.sql` script to create tables (can be done remotely or via an initial seed script).
3. **Application Packaging:**
   - Build the Docker images for the backend and frontend.
   - *Note:* Since we do not use an external Docker Registry (ECR) to save money, the script should tarball the images or use SSH to build/load them directly into the EC2 instance's K3s image cache (`k3s ctr images import`).
4. **Kubernetes Orchestration:**
   - Copy the `k8s/` manifests folder to the EC2 instance via SCP.
   - Connect via SSH to the EC2 instance and trigger `kubectl apply -f k8s/` to start the pods.
5. **Output Delivery:**
   - Print out the final HTTP URL to access the working web platform application.

Please generate all files, code structures, and configurations keeping everything modular, readable, and functional.
